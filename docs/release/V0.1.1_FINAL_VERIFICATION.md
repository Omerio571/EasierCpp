# EasierCpp v0.1.1 — two-feature release verification

## Scope and existing work

The independent window position/size implementation and version 0.1.1 were already
complete when this follow-up began. Their uncommitted changes were retained. No
second placement system, preference format or GUI redesign was introduced.
Position ON/Size OFF remain the new-project defaults. Existing full restoration ON
migrates to both ON; OFF migrates to both OFF. Geometry records remain compatible;
enabled legacy session preferences use persistent retention in the new UI.

## Automatic initial run

Opening a project with Auto Run enabled queues one initial build/launch. Enabling
Auto Run while idle does the same; an already running application is preserved.
The existing GUI timer, scheduler, build worker, File API reader, freshness services,
process supervisor and A/B replacement pipeline perform the work. Startup has no
separate checkbox or compilation implementation.

An initial-only require-target guard resolves a saved valid target or the sole
current executable. Ambiguous graphs pause before target compilation; the existing
form helper asks for a choice. Cancelling leaves the workspace selector available.
A Run request queued during discovery cannot bypass target selection.

Focused tests exposed stale cached sole-target metadata after an external CMake edit.
Initial startup now checks Ninja's existing regeneration dependencies before target
selection. Missing/suppressed regeneration and other generators use normal authorized
configuration. Cold configuration is not repeated unnecessarily, warm unchanged
artifacts are reused, and ordinary save/replacement cycles are unchanged.

Configuration/write approval remains in the existing authorization path. Failure
retains the Auto Run preference for recovery on a later save. Stop/OFF/close cancel
startup; switching during initial compilation cancels/drains the obsolete owned job
before opening the next project. Pending edits use existing coalescing/freshness checks.

Context7 was used to check the official [CMake File API documentation](https://cmake.org/cmake/help/latest/manual/cmake-file-api.7.html):
target replies describe a generated graph, so startup must refresh that graph before
making an ambiguous target decision. No additional tools/dependencies were installed.

## Limits and publication

Auto Run can pause for target selection, presets/toolchain correction or approval.
Untrusted CMake is not a sandbox: review code before authorizing it. Seamless mode
is experimental for exclusive-instance/resources and some launchers; Safe remains
available. Geometry is best effort for application-controlled fullscreen/startup
changes. Physical multi-monitor/mixed-DPI and individual SDL/SFML acceptance remain
manual. No clean-VM/cross-machine or universal library compatibility claim is made.

The Windows 11 x64 portable package requires the supported Microsoft runtime.
Compiling projects requires installed compiler/SDK/build tools; none are bundled.
No permanent PATH changes, user-data deletion, commit, tag, push or publication
were performed. Older local artifacts are retained.
