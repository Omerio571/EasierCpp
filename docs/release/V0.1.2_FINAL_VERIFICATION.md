## Compatibility and limits

Windows 11 x64 and Visual C++ v14 x64 runtime are needed. Compiling projects requires
separately installed compiler/SDK/CMake/Ninja; the ZIP is not a bundled toolchain or
USB-contained settings mode. Runtime resources resolve beside the executables.
Portable production code has no compiled source-checkout fallback.

SDK skipping is limited to verified default MSVC/x64 Ninja profiles (blank or explicit
`-` default preset choice). Named presets, custom toolchains/vcpkg, other compilers/
generators and uncertain imports retain conservative setup. An application depending
on SDK environment variables or uninspectable dynamic DLL loading can force the full
path with `EASIERCPP_REQUIRE_DEVELOPER_ENV=1` in its launching environment. This is
process-local; no permanent PATH changes are required. Moving manager resources may
invalidate a path-sensitive project/PCH cache; use the normal approved recovery flow.

The new `base` active pointer is not understood by older binaries. Do not mix manager
versions on shared state. Preserve old projects/settings/caches and consult
[the compatibility guide](../development/AUTO_RUN_BUILD_TREES.md) before downgrading.
For comparisons use isolated state. No cache/state deletion is an upgrade step.

Safe mode closes the old instance after successful compilation; Seamless retains it
while validating the new candidate, unsuitable for some exclusive-instance apps.
First visibility and completed handoff are different. No application memory migration,
Snap Groups, universal library compatibility or guaranteed subsecond update is claimed.
Clean-machine/other-computer, Windows reboot, physical mixed-DPI/multimonitor, real
FarmGame and each graphics framework remain manual acceptance. The package is unsigned.

## Installation, upgrade and owner acceptance

1. Close the old manager and its managed applications. Keep existing project folders,
   settings and compilation caches. Extract the complete new ZIP into a fresh writable
   folder. New users install the external prerequisites described in its README.
2. Run EasierCpp-Gui.exe from that folder. Expect v0.1.2 in the title. Run Tools
   diagnostics, or `EasierCpp.exe doctor` from ordinary PowerShell; installed tools
   need not be available on that terminal's PATH.
3. Create a disposable calculator outside the package; test Debug and Release, enter
   a name/two numbers, and expect the correct sum. Test manual Build/Run/Stop/Restart.
4. Enable Auto Run on an idle disposable project: expect initial launch. Save a real
   edit: expect incremental replacement. The first alternate can still be cold; the
   next update should return to the original tree. Same-content saves should not restart.
5. Introduce a compile error: expect clear output and a retained working app. Repair
   and save: expect replacement. Rapid edits should ultimately run the latest code.
   Stop must pause automatic launch; Auto Run OFF must disable automatic work.
6. Use a disposable copy of a graphical project. Test Safe and Seamless, move/resize
   its window, and verify position/size preferences. Seamless may show the new window
   while the old process remains briefly protected. Use Safe for exclusive resources.
7. Close/reopen the manager and project; verify settings/target and cached builds.
   Test a trusted local library with the normal project-change approval; inspect an
   external library without destructive edits. Real FarmGame, graphics assets/input,
   other computers and physical displays need owner acceptance; not claimed here.
8. Check the archive with `Get-FileHash -Algorithm SHA256` and compare the hash above
   or the .sha256 file. Do not delete state or caches when upgrading. Review the
   documented `base` pointer caveat before any downgrade.
