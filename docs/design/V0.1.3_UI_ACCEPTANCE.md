# EasierCpp v0.1.3 UI Overhaul acceptance

Run [EasierCpp-Gui.exe](../../build/ui-v0.1.3-final/EasierCpp-Gui.exe) from the Release
build directory. Keep its companion executable and resources together. Use a
disposable CMake project outside the manager directory for acceptance.

1. **Home.** Check the EasierCpp mark in the native title bar and welcome card.
   Create a calculator or open an existing disposable project. Return to Home,
   reopen it from the recent list, and remove a recent entry to verify that this
   only removes the shortcut.
2. **Workspace.** Select Debug or Release and an executable target. Build, Run,
   Stop, and Restart. An unopened or unconfigured build tree may have no target
   list yet. Build first, then check the available targets. Enter calculator input
   using Enter and Send. Switch between
   Program Console and Build & System and clear one console.
3. **Auto Run.** Enable it and save a source change while the program is running.
   Check that the old process survives compilation and that the new process runs
   after success. Introduce and fix a compile error. Try Safe and Seamless using
   a disposable graphical fixture and check window position and size restoration.
4. **Libraries.** Open Manage libraries from the Workspace. In the manager, switch
   categories and search for a known name and a missing name. Inspect a detected
   dependency and check its read-only status. Add a trusted local library to a
   disposable project, review the exact changes, approve, and verify the build.
   Edit or remove the integration and review the proposed changes again.
5. **Project and Tools.** Open Project Settings, review launch options, and cancel
   a proposed edit. Open the preferred editor, run Doctor, and inspect the result
   in Build & System. Check the test runner and worker optimizer separately.
6. **Settings and accessibility.** Leave the calculator waiting for input. In
   Settings → Appearance, try Light, Dark and Follow Windows. Return to Workspace
   and check both console backgrounds, retained output and working input. Hover,
   click and Tab to each Workspace information icon. Enter and Space should open
   help. Escape and a click elsewhere should dismiss it. With Appearance open,
   change the theme and click Preferred Editor. Choose No to keep the pending
   edit, or Yes to discard it and switch sections. Cancel should discard the
   pending edit as well. Open Window & Process and check
   position, size, and replacement options. Close and reopen the app to verify
   saved preferences.
7. **Resize and Windows shell.** Check the two-row toolbar in a narrow window
   and the single-row toolbar at a wide size. Inspect the executable icon in
   Explorer and the running app in the taskbar and Alt+Tab.

The Home recent list and the Libraries summary use live manager state. Routine
forms open below the parent page's heading and section controls. Operation
progress, change previews, approvals, and system pickers can open separate
windows. The app uses native Windows window chrome.

The [branding comparison](../../assets/branding/comparison.png) shows the original
Aseprite art and the SVG exports at 16, 24, 32, 48, 64, 128, and 256 px. The source
and editable SVG master live alongside the PNG and ICO files.

## Final refinements

The real GUI passed the native help and subsection checks in both themes,
including all four Workspace icons, keeping or discarding pending Appearance
changes, saving a project working directory, and cancelling a local library
edit without changing the pin. [Light Settings](../../build/ui-v0.1.3-final/detail-screenshots/settings-light.png)
and [Dark Settings](../../build/ui-v0.1.3-final/detail-screenshots/settings-dark.png)
show Appearance below the unchanged Settings controls. Quick passed 39/39
in 28.49 s, and the focused GUI lifecycle and local GitLab fixtures passed 2/2
in 60.26 s. The native test delivers Win32 input messages; manually checking
physical hover and Tab order remains part of acceptance.

## Earlier integration repair

The Release executable reports file and product version 0.1.3.
[Light](../../build/ui-v0.1.3/ui-repair-screenshots/workspace-light.png) and
[Dark](../../build/ui-v0.1.3/ui-repair-screenshots/workspace-dark.png) show the
actual application on the same disposable project. The native GUI test checked
the caption, live icons, inline Appearance and Libraries forms, persistence,
three library categories, search, and sidebar navigation. The focused UI suite
passed 3/3 in 69.67 s. It also checked both Rich Edit backgrounds and preserved
program output, process identity, and input availability during a theme switch.

Quick passed 39/39 in 28.88 s before the final integration checks. The final
offline Full run passed 62/62 in 496.24 s and included all 39 Quick checks.
It excluded `stage5_libraries` and `stage5_unified_raylib`, which download
dependencies. The optional live-library suite was outside this selection.
The first build needed the Windows theme declaration header. The initial GUI
search probe failed until it sent keyboard input to the actual search control
and retrieved the result through a cross-process Windows message.

Physical mixed-DPI transitions, taskbar and Alt+Tab appearance, and a manual
hover/keyboard walkthrough remain acceptance checks. The previous replacement
benchmark below predates this repair.

## Earlier integration verification

Windows x64 Release, C++20, MSVC and Ninja. Both executable FileVersion and
ProductVersion and the generated release version report 0.1.3. The native
restart regression checks the actual GUI's caption, version in Settings, extractable icon
resource, and the large and small icon handles returned by the live window.
An interactive window-activation request timed out during visual inspection.
Direct visual confirmation of the taskbar and Alt+Tab is an owner check.

The initial Quick suite caught an overlap at the target help button. The
corrected layout passed Quick 39/39, including all six destinations at narrow,
ordinary and wide window sizes in Dark, Light and Follow Windows. The final
paint and layout run passed Quick 39/39 in 28.97 s. The focused native GUI audit,
real GUI restart and lifecycle tests passed 3/3 in 85.68 s.

The last rebuild tied Tools' Run Tests and Cancel Running Tests buttons to the
test lifecycle and refreshed project actions while work is active. Native
restart, layout, and lifecycle then passed 3/3 in 74.68 s. The lifecycle test
asserts that the Tools buttons switch correctly through real cancellation.

The offline Full selection first passed 61/62 in 561.71 s. The lifecycle test
hit its 180-second timeout while opening a compiler diagnostic. The hidden
console now receives a viewport and diagnostic navigation reads a logical
line across visual wrapping. The same lifecycle test passed on focused
retest in 59.94 s and again after the paint update in 58.57 s. The timeout
remains in the original Full log. The excluded tests were
`stage5_libraries`, `stage5_unified_raylib`, and the optional
`stage5_live_libraries` suite. The offline GitHub/GitLab workflows and
local-library consumers ran within the offline selection.

The shell console's information, success, warning, and error text contrast
ratios against the approved backgrounds were respectively 6.60, 9.63, 10.05,
and 4.87 on light, and 7.14, 10.42, 10.87, and 5.27 on dark.
